# Release Pipeline & Self-Update Design

## Context

`vscode-ldf-explorer` is distributed as a `.vsix` file rather than through the VS Code Marketplace. The repository currently has no release pipeline and no in-extension update mechanism.

## Goals

1. Provide a maintainable GitHub Release pipeline triggered by version tags on a dedicated `release` branch.
2. Add an in-extension updater that checks the latest GitHub Release, prompts the user, downloads and installs the `.vsix`, and reloads the window.

## Decisions

- **GitHub repository**: `notdog1998/FV_LDF_Parser`, public.
- **Release asset name**: `fv-ldf-explorer.vsix` (fixed, no version in filename).
- **Update prompts**: English, consistent with the rest of the extension.
- **Prereleases**: no special handling; any `tag_name` matching `v*.*.*` is compared via semver.
- **No CHANGELOG**: release notes will be auto-generated by GitHub.

## Release Pipeline

### Branch Model

- `main` remains the daily development branch.
- A long-lived `release` branch holds the clean release state.
- To publish: bump the version in `main`, merge/synchronize `main` into `release`, then push a tag `v*.*.*` on `release`.

### Workflow `.github/workflows/release.yml`

Trigger: `push` to `release` with a tag matching `v*.*.*`.

Steps:

1. Checkout `release` at the pushed tag.
2. Install Node and run `npm ci`.
3. Build: `npm run compile` and `npm run build:webview`.
4. Package with `vsce package`.
5. Verify the tag version (without leading `v`) equals `package.json` version; fail if mismatched.
6. Rename the produced `.vsix` to `fv-ldf-explorer.vsix`.
7. Create a GitHub Release with `softprops/action-gh-release`:
   - Title = tag name
   - Asset = `fv-ldf-explorer.vsix`
   - Body generated via `--generate-notes`
8. Declare `permissions: contents: write`.

### Packaging Hygiene

`.vscodeignore` will be updated to exclude development-only files while keeping runtime dependencies and the pre-built bridge executable.

## In-Extension Updater

### Module: `src/updater.ts`

Responsibilities:

- Query the GitHub Releases API for the latest release.
- Compare remote `tag_name` with the local `package.json` version using `semver`.
- Prompt the user when a newer version is available.
- Download the `.vsix` asset to `context.globalStorageUri`.
- Install via `workbench.extensions.action.installVSIX`.
- Handle errors gracefully, especially during automatic checks.

### Activation Behavior

- `activate()` calls `checkUpdate(context, { silent: true })` without awaiting it.
- The call is wrapped so no uncaught exception can block activation.
- Respects `ldfExplorer.autoCheckUpdate` (default `true`).

### Manual Check

- Command `ldfExplorer.checkUpdate` calls `checkUpdate(context, { silent: false })`.
- Registered in `contributes.commands` and the command palette.

### API Request

- `GET https://api.github.com/repos/notdog1998/FV_LDF_Parser/releases/latest`
- Headers: `Accept: application/vnd.github+json`, `User-Agent: vscode-ldf-explorer/<version>`
- For public repos no token is required; `ldfExplorer.githubToken` is used as `Authorization: Bearer <token>` if provided.
- Request timeout: 10s for API calls.

### User Prompt

```
A new version of LDF Explorer is available: x.y.z
[Update Now] [View Release Notes] [Ignore This Version]
```

- **Update Now**: shows a progress notification, downloads the asset (30s timeout), installs the `.vsix`, then prompts to reload the window.
- **View Release Notes**: opens the release HTML page in the default browser.
- **Ignore This Version**: stores the version in `context.globalState` under a known key; that version is skipped in future checks.

### Download & Install

- Locate the asset whose name ends with `.vsix` (preferring `fv-ldf-explorer.vsix`).
- Ensure the target directory under `context.globalStorageUri` exists.
- Delete any previously downloaded `.vsix` files in that directory before writing.
- Verify HTTP 200; otherwise show a clear error message.
- After download, call `vscode.commands.executeCommand('workbench.extensions.action.installVSIX', vscode.Uri.file(vsixPath))`.
- On success, prompt the user to reload the window.

### Error Handling

| Scenario | Automatic Check | Manual Check |
|----------|----------------|--------------|
| Network error | Log to output channel | Show error message |
| API rate limit (403) | Log to output channel | Show message with guidance |
| No release (404) | Log to output channel | Show info message |
| Download/install failure | Log + show message | Show error message |

All errors must be caught and must not crash activation.

## Configuration

Add to `contributes.configuration`:

- `ldfExplorer.autoCheckUpdate`: `boolean`, default `true`.
- `ldfExplorer.githubToken`: `string`, default `""`, for private-repo tokens.

## Dependencies

Add `semver` to `dependencies` so it is bundled into the `.vsix`.

## README Updates

Add a "Publishing" section documenting the maintainer flow:

1. Update `package.json` version.
2. Merge `main` into `release`.
3. Push tag `v<version>` on `release`.
4. GitHub Actions creates the Release and uploads `fv-ldf-explorer.vsix`.

## Acceptance Criteria

1. Pushing a test tag on `release` produces a GitHub Release with the `.vsix` attached.
2. Local version lower than remote triggers the update prompt on activation.
3. "Update Now" downloads, installs, and prompts to reload; after reload the new version is active.
4. Offline / no-release scenarios do not error or hang activation.
5. A brief maintainer guide and user guide are included in the final summary.
